Документация проекта: MVP Распределения груза по осям
📌 Описание продукта
SaaS-приложение для дальнобойщиков-частников, решающее проблему безопасного распределения груза по осям транспортного средства (ТС).
Главная ценность: предотвращение штрафов на весовом контроле и снижение риска аварий из-за неправильной центровки. Пользователь вводит параметры груза, а приложение само рассчитывает безопасные позиции в кузове и выдает 2D-визуализацию.

🛠 Технический стек
Язык: Python 3.13

UI-фреймворк: Flet 1.0+ (выбран для возможности сборки в полностью оффлайновый нативный .apk под Android, так как целевой аудитории часто приходится работать без интернета на трассе).

Архитектура: Изолированная бизнес-логика. Расчетное ядро ничего не знает об интерфейсе, данные ходят через абстракции интерфейсов.

🗂 Структура модулей
1. core/ (Бизнес-логика и физика)
models.py: Дата-классы. Содержит структуру ТС (Truck), осей (AxleGroup) и груза (Cargo). Кузов транспортного средства отвязан от передней оси через параметр body_start_offset (смещение кабины).

physics.py: Расчетное ядро. Использует метод моментов сил статического равновесия. Считает моменты относительно передней оси. Выдает предупреждения двух уровней: обычный перегруз (превышение допустимой массы) и критическая ошибка (отрыв оси из-за отрицательной нагрузки, потеря сцепления).

optimizer.py: Алгоритм автоматической расстановки груза. Работает по эвристике "Сплошного блока" (Sliding Block) в 1D-пространстве (только по длине).

interfaces.py: Абстрактные базовые классы. Задает контракт CargoDataSource для будущего подключения внешних API.

2. data/ (Источники данных)
manual_source.py: Реализация CargoDataSource для ручного ввода грузов. Хранит данные в оперативной памяти (in-memory state). Подготовлена почва для создания AtiSuCargoDataSource.

3. ui/ (Интерфейс на Flet)
app.py: Точка входа в UI. Связывает состояние (создает сессию Truck и список грузов) и вызывает рендер компонентов.

components.py: Карточки транспортного средства и форма ввода/управления грузами.

visualizer.py: 2D-рендер на базе flet.canvas. Отрисовывает шасси, позицию кабины, оси и расставленные грузы в строгом соответствии с физическими координатами, рассчитанными в ядре.

🧠 Как работает алгоритм оптимизации (optimizer.py)
Из-за комбинаторного взрыва полноценный 3D bin packing для мобильного процессора не подходит. Алгоритм использует упрощенную, но "жизненную" модель:

Склейка: Грузы группируются вплотную друг к другу в единый блок.

Скольжение: Блок с шагом в 10 см "едет" от передней стенки кузова к задним воротам. На каждом шаге вызывается physics.py.

Функция штрафов (Cost Function): Из всех вариантов, где нет перегрузов, алгоритм ищет баланс.

Он минимизирует разницу в процентах загрузки между передней и задней осями.

Применяет штраф за дистанцию. Легкие грузы прижимаются максимально близко к кабине (так грузят в реальности для фиксации), а тяжелые алгоритм уводит назад ровно на столько, сколько нужно, чтобы спасти переднюю ось от перегруза.

🚧 Текущие ограничения MVP
Типы ТС: Поддерживаются только "одиночки" (жесткий грузовик, например КамАЗ 4308). Тягачи с полуприцепами (фуры) отключены на этом этапе, так как передача массы через седло требует другой формулы моментов.

Габариты: Поддерживается только 1D-позиционирование (длина). Ширина и высота не учитываются.

Интеграция ATI.SU: Реализована только на уровне архитектурной заглушки. HTTP-запросы к API биржи не производятся.
